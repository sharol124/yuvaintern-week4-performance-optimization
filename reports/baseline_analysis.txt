WEEK 4 – BASELINE PERFORMANCE ANALYSIS

Project: Student Records Management System
Phase: Before Optimization

1. Testing Environment

Programming Language: Python 3.10
Dataset Size: 10,000 student records
Benchmark Runs: 3
Profiling Tool: cProfile
Execution Time Tool: timeit

2. Benchmark Results

Total Execution Time: 30.498892 seconds
Average Execution Time: 10.166297 seconds

3. Identified Performance Bottleneck

The profiling results identified the sort_students_by_marks()
function as the primary performance bottleneck.

The function consumed approximately 7.237 seconds of
exclusive execution time and 7.239 seconds of cumulative
execution time.

4. Root Cause

The original application uses the Bubble Sort algorithm
to arrange student records according to their marks.

Bubble Sort has O(n²) time complexity. Its performance
decreases significantly when processing large datasets.

5. Proposed Improvements

- Replace Bubble Sort with Python's built-in sorted()
  function.
- Implement dictionary-based student searching.
- Reduce unnecessary iterations.
- Improve calculation efficiency.

6. Conclusion

The baseline profiling results demonstrate that sorting
is the major performance bottleneck in the original
application.

The next phase will implement optimization techniques
and compare the results against these baseline measurements.
